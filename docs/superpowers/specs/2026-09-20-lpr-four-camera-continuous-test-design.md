# LPR 4카메라 연속수신 시험 설계

## 1. 목표

한 LPR 장비가 최대 4개 카메라 연결을 동시에 유지하며 연속으로 파일명 사건을 전송할 때 `Parking.EdgeService`가 프레임을 빠뜨리거나 연결을 혼동하지 않고 각 사건에 ACK 또는 NAK를 반환하는지 반복해서 검증한다.

이번 단계는 운영 LPR 프로그램을 변경하지 않는다. 실제 장비와 같은 STX/ETX, KS5601(CP949) TCP 패킷을 만드는 전용 시험 도구와 한 번에 실행할 수 있는 배치 파일을 추가한다.

## 2. 구성

### Parking.LprStressTester

- 위치: `src/Tools/Parking.LprStressTester`
- 형식: .NET 9 콘솔 프로그램
- 연결: 카메라 수만큼 `Parking.EdgeService:29200`에 독립 TCP 연결
- 기본 카메라 수: 4
- 각 카메라는 서로 다른 LPR `devicenum`을 사용한다.
- 각 연결은 지정 횟수만큼 입차 파일명을 순서대로 전송하고 매 패킷의 응답을 기다린다.
- 파일명은 기존 `LprFileNameParser` 규칙을 그대로 사용한다.
- 동일 차량의 중복입차 판정과 충돌하지 않도록 사건마다 서로 다른 차량번호를 사용한다.

### 공유 프로토콜

시험 도구가 EdgeService 내부 프로젝트를 참조하지 않도록 STX/ETX와 CP949 인코딩, ACK/NAK 응답 해석을 시험 도구 안의 작은 프로토콜 클래스로 분리한다. 운영 규격과 다른 응답, 응답 제한시간 초과, 연결 종료는 실패로 집계한다.

## 3. 실행 인수

| 인수 | 기본값 | 설명 |
|---|---:|---|
| `--host` | `localhost` | EdgeService 주소 |
| `--port` | `29200` | LPR TCP 포트 |
| `--site` | `9001` | 현장번호 |
| `--group` | `2` | 그룹번호 |
| `--lane` | `9010` | 입차 차로 ID |
| `--devices` | `101,102,103,104` | 카메라별 LPR devicenum |
| `--count` | `20` | 카메라별 전송 횟수 |
| `--interval-ms` | `50` | 사건 사이 간격 |
| `--timeout-seconds` | `10` | 연결 및 응답 제한시간 |

장비 목록의 개수는 1~4개만 허용한다. 숫자 범위나 필수 인수가 잘못되면 연결 전에 사용법과 오류를 출력하고 종료코드 1을 반환한다.

## 4. 결과와 종료코드

카메라별로 전송, ACK, NAK, 제한시간 초과, 연결 오류를 집계하고 마지막에 전체 합계를 출력한다.

- 모든 사건이 ACK: 종료코드 0
- 인수 오류: 종료코드 1
- NAK, 제한시간 초과, 연결 오류 또는 응답 누락: 종료코드 2

각 응답의 EventId가 존재하는지도 확인한다. ACK 수와 전송 수가 다르면 성공으로 처리하지 않는다.

## 5. 자동시험

- 1~4개 장비 목록 인수 해석
- 5개 이상 장비 거부
- STX/ETX와 CP949 요청 생성
- 분할 수신된 ACK 프레임 조립
- ACK, NAK, 잘못된 응답 구분
- 전체 전송 수와 ACK 수가 같은 경우만 성공 판정

TCP 통합시험은 가짜 TCP 서버로 네 연결을 동시에 받고 각 패킷에 서로 다른 EventId ACK를 반환해 연결별 연속송수신을 검증한다. 실제 MySQL과 EdgeService 실행시험은 배치 파일에서 수행한다.

## 6. 일괄 실행

저장소 최상위에 `run-lpr-four-camera-test.bat`를 둔다.

1. `PARKING_TEST_CONNECTION` 존재 확인
2. Parking.Api 실행 후 `pause`
3. Parking.EdgeGateway 실행 후 `pause`
4. Parking.EdgeService 실행 후 `pause`
5. LPR 4카메라 시험 실행 후 결과 확인
6. MySQL에서 시험 시간 이후 입차 건수 조회 후 `pause`

배치 파일은 연결 문자열을 소스에 저장하지 않고 환경변수에서 전달한다. 기존 현장 설정을 사용하며 데이터 디렉터리를 별도로 덮어쓰지 않는다.

## 7. 완료 기준

- 새 프로젝트와 자동시험이 `ParkingSystem.sln`에 포함된다.
- 전체 솔루션 빌드와 자동시험이 성공한다.
- 네 TCP 연결이 동시에 유지되고 설정 횟수만큼 ACK를 받는다.
- 실패가 하나라도 있으면 시험 도구가 성공 종료하지 않는다.
- 실행 방법과 결과 확인 방법이 `docs/04-development-status.md`에 기록된다.

## 8. 제외 범위

- 운영 LPR 카메라 펌웨어 변경
- 4개를 초과하는 카메라 부하시험
- 출차 무인정산 SignalR 시험
- 성능 목표 TPS 산정
- 장시간 안정성 시험의 자동 스케줄링
