# 로컬 환경설정 및 영상 서버 설계

## 목적

각 주차장은 중앙 서버 연결 여부와 관계없이 독립적으로 운영되어야 한다. 현장 설정의 원본은 EdgeService의 로컬 SQLite에 저장하고, 중앙 서버는 여러 주차장의 설정을 통합 보관한다. LPR 영상은 현장 폴더에 먼저 저장한 뒤 ImageUploadAgent가 ParkImageServer로 전송하며, 다른 프로그램은 파일명으로 영상을 조회한다.

## 설정 소유권

- 현장 설정의 원본은 각 주차장의 로컬 SQLite이다.
- 로컬에서 추가·수정·삭제한 설정은 중앙 서버로 전송한다.
- 중앙에서 수정한 설정은 해당 주차장의 EdgeService로 전송한다.
- 양쪽에서 변경된 경우 설정별 버전과 수정시간을 비교하여 마지막 변경값을 적용한다.
- 통신이 끊겨도 마지막 로컬 설정으로 계속 운영하며, 연결 복구 후 미전송 변경을 동기화한다.

## 최초 등록

EdgeService 로컬 DB가 비어 있으면 EdgeManager가 최초 설정 화면을 표시한다. 관리자가 다음 값을 직접 입력한다.

- 중앙 서버 주소
- 이미지 서버 주소
- `sitenum`
- 중앙에서 발급한 현장 인증키

저장 후 EdgeService는 중앙 서버에 현장을 인증하고 기본 현장정보를 받는다. 자동으로 `sitenum`을 만들거나 다른 주차장을 추측하지 않는다.

## 로컬 설정 범위

로컬 SQLite는 다음 설정을 관리한다.

- 현장정보
- 차로정보: `groupnum`, `laneid`, 명칭, 방향, 사용 여부
- 장치정보: `deviceid`, `devicenum`, `devicename`, `devicetype`, IP, Port, 사용 여부
- 장치 연결정보: LPR, 무인정산기, 전광판, 차단기 사이의 연결관계
- 로컬 수신 Port
- 중앙 서버 주소와 이미지 서버 주소
- 영상 감시폴더 및 필요한 로컬 저장경로
- 요금, 할인, 운영변수

EdgeService만 SQLite를 직접 사용한다. EdgeManager, LPR, 무인정산기, ImageUploadAgent 등은 EdgeService의 로컬 설정 API를 사용한다.

## 설정 변경 및 동기화

1. EdgeManager가 EdgeService 로컬 설정 API로 설정을 추가·수정·삭제한다.
2. EdgeService는 SQLite 트랜잭션으로 설정과 변경 버전을 저장한다.
3. 같은 트랜잭션에서 설정 동기화 Outbox를 기록한다.
4. 동기화 Worker가 중앙 서버로 변경내용을 전송한다.
5. 중앙 변경은 현장별 연결을 통해 EdgeService가 받고 같은 버전 규칙으로 적용한다.
6. 전송 실패 항목은 삭제하지 않고 재시도한다.

삭제는 동기화 중 누락되지 않도록 삭제표시와 버전을 전송한 뒤 양쪽에 반영한다.

## 프로그램별 역할

### EdgeService

- 로컬 설정 DB와 설정 API 제공
- 현장 인증 및 중앙 동기화
- 운영 프로그램에 해당 현장 설정만 제공
- 설정 변경 Outbox 재전송

### EdgeManager

- 최초 서버 연결정보 입력
- 현장·차로·장치·장치 연결·요금·할인·운영변수의 추가·수정·삭제
- 동기화 상태와 오류 표시
- 입출차 목록 및 영상 표시

### LPR

- EdgeService에서 자신의 장치정보와 영상폴더 설정 조회
- 인식 영상을 로컬 감시폴더에 저장
- 입출차 이벤트에는 전체 경로가 아닌 영상 파일명만 기록

### ImageUploadAgent

- 설정된 로컬 폴더를 주기적으로 검사
- 완전히 기록된 영상만 ParkImageServer에 업로드
- 서버에 같은 파일이 있거나 업로드가 성공하면 로컬 파일 삭제
- 실패하면 파일을 유지하고 다음 검사에서 재시도

### ParkImageServer

- `POST /api/image/upload`: `multipart/form-data`의 `file`, `fileName` 수신
- `GET /api/image/exists?fileName=...`: 존재 여부 확인
- `GET /api/image/download?fileName=...`: 영상 반환
- 새 파일명에서 촬영일을 읽어 `RootPath/yyyy/MM/dd` 아래 저장

## 영상 파일명

새 시스템은 다음 형식만 사용한다. 기존 파일명 호환 처리는 하지 않는다.

`{sitenum}_{groupnum}_{devicenum}_{laneid}_{Entry|Exit}_{yyyyMMddHHmmssfff}_{차량번호}_{EventId}.jpg`

예:

`9001_002_201_9020_Exit_20260920105052407_56다7890_6154c145aac64f3aba5a871fb6457172.jpg`

ParkImageServer는 `_`로 분리한 여섯 번째 항목의 앞 8자리를 연·월·일로 사용한다. 파일명은 단일 파일명만 허용하고 절대경로, `..`, 디렉토리 구분자를 거부한다.

## 영상 조회

EdgeManager와 무인정산기는 EdgeService에서 받은 이미지 서버 주소와 이벤트의 파일명을 사용한다.

`{ImageServerBaseUrl}/api/image/download?fileName={escapedFileName}`

다운로드한 데이터가 없거나 HTTP 오류이면 기존 화면을 중단하지 않고 해당 사진만 비운다. 새 선택 요청이 이전 요청보다 늦게 끝나더라도 오래된 사진이 현재 선택을 덮어쓰지 않도록 선택별 취소 또는 요청번호를 적용한다.

## 데이터 분리

- 모든 설정과 이벤트는 `sitenum`을 필수 경계로 사용한다.
- EdgeService는 최초 등록된 하나의 `sitenum` 데이터만 저장하고 제공한다.
- 중앙 서버는 여러 주차장 데이터를 저장하지만 모든 조회·변경에 `sitenum`과 현장 인증을 적용한다.
- 장치 식별은 현장 내 `devicenum`을 사용하고, 내부 참조에는 `deviceid`를 사용한다.

## 오류 처리

- 중앙 서버 장애: 로컬 운영 계속, Outbox 재시도
- 이미지 서버 장애: 원본 로컬 영상 유지, 업로드 재시도
- 잘못된 파일명: 업로드·조회 거부 및 로그 기록
- 잘못된 현장 인증: 설정 동기화 거부, 기존 로컬 설정 유지
- 설정 충돌: 버전과 수정시간을 비교하여 마지막 변경 적용

## 검증

- 빈 DB에서 최초 설정 저장 및 재시작 후 복원
- 현장별 설정 격리
- 차로·장치·연결정보 CRUD와 중앙 동기화
- 통신 단절 중 변경 후 복구 동기화
- 새 파일명 날짜 경로 저장
- 영상 업로드, 존재확인, 다운로드
- 업로드 실패 시 로컬 파일 유지 및 재시도
- EdgeManager 행 선택 시 입차·출차 영상 표시
- 빠른 행 선택 변경 시 오래된 다운로드 결과 무시
