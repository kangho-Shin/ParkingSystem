# Parking.EdgeManager 최소 기능 설계

## 1. 목적

`Parking.EdgeManager`는 현장 담당자가 `Parking.EdgeService`의 연결 상태와 실제 입차·정산·출차 흐름을 한 화면에서 확인하는 Windows용 관리 프로그램이다. 1차 버전은 조회와 모니터링에 집중하며 설정 변경이나 장비 제어는 하지 않는다.

## 2. 범위

### 포함

- `Parking.EdgeService`, `Parking.EdgeGateway`, 중앙 API 연결 상태 표시
- 마지막 현장 설정 동기화 시각과 현장·그룹·차로·장비 설정 조회
- 현재 입차 차량 목록 표시
- 정산·출차 통합 처리 목록 표시
- 새 입차·정산·출차 발생 시 LPR 사진 자동 표시
- 목록에서 선택한 차량의 LPR 사진 표시
- 1초 간격 자동 갱신

### 제외

- 현장 설정 수정
- 로그 파일 조회
- CPU, 메모리, 디스크 사용량 감시
- 원격 차단기 개방과 장비 제어
- 사용자 로그인과 권한 관리
- 중앙 서버의 과거 입출차 이력 조회

## 3. 프로그램 구조

### Parking.EdgeManager

- .NET 9 WinForms 프로그램으로 만든다.
- `Parking.EdgeService`의 관리 API만 호출한다.
- SQLite 파일이나 LPR 이미지 폴더를 직접 열지 않는다.
- 기본 EdgeService 주소는 `http://localhost:5200`이며 설정 파일에서 변경할 수 있다.

### Parking.EdgeService

- 기존 입차·출차·정산 처리 시 모니터링 데이터를 SQLite에 함께 저장한다.
- EdgeManager가 사용할 상태, 목록, 설정, 이미지 조회 API를 제공한다.
- 중앙 연결 장애 중에도 현장에 접수된 사건은 즉시 모니터링 목록에 반영한다.
- Outbox 재전송 결과에 따라 중앙 전송 상태를 갱신한다.

### Parking.EdgeGateway

- 상태 확인 API를 제공한다.
- Gateway 프로세스 자체 상태와 `Parking.Api` 연결 결과를 구분해서 반환한다.
- EdgeService는 이 결과를 사용해 화면의 Gateway와 중앙 상태를 각각 표시한다.

### 공통 계약

관리 API의 요청·응답 모델은 `Parking.Contracts`에 둔다. JSON 속성명은 기존 규칙대로 PascalCase를 유지한다.

## 4. 화면 구성

화면은 크기 조절이 가능한 단일 WinForms 창으로 구성한다.

1. 상단 상태 영역
   - EdgeService 상태
   - EdgeGateway 연결 상태
   - 중앙 API 연결 상태
   - 마지막 설정 동기화 시각
2. 왼쪽 입차 목록
   - 현재 주차 중인 차량만 표시
   - 최신 입차 순으로 정렬
3. 가운데 처리 목록
   - 정산과 출차를 같은 목록에 표시
   - 처리 종류를 `정산`, `출차`로 구분
   - 최신 처리 순으로 정렬
4. 오른쪽 LPR 사진 영역
   - 입차 사진
   - 출차 사진
5. 하단 설정 영역
   - 사이트, 그룹, 차로, 장비 설정을 읽기 전용으로 표시

## 5. 목록 동작

### 입차 목록

- 입차 요청을 받으면 즉시 추가한다.
- 최대 1,000대를 유지한다.
- 정상 출차가 완료되면 같은 차량의 입차 행을 삭제한다.
- 출차가 차단되거나 실패하면 입차 행을 유지한다.
- 동일 차량의 여러 주차 건은 `ParkingSessionId` 또는 `EventId`로 구분한다.

### 정산·출차 처리 목록

- 정산 완료 요청마다 한 행을 추가한다.
- 출차 요청마다 별도의 한 행을 추가한다.
- 한 차량이 정산 후 출차하면 `정산` 한 행과 `출차` 한 행이 각각 남는다.
- 최근 1,000건을 유지한다.
- 1,000건을 초과하면 발생시각이 가장 오래된 행부터 삭제한다.
- 중앙 전송 상태는 `완료`, `대기`, `실패`로 표시한다.
- 출차 행에는 차단기 개방 여부와 처리 결과 코드를 표시한다.
- 정산 행에는 정상요금, 할인금액, 결제금액, 결제수단을 표시한다.

## 6. LPR 사진 동작

- 입차가 발생하면 해당 입차 사진을 즉시 표시한다.
- 정산이 발생하면 해당 차량의 입차 사진을 즉시 표시한다.
- 출차가 발생하면 해당 차량의 입차 사진과 출차 사진을 즉시 나란히 표시한다.
- 사용자가 목록 행을 선택하면 선택 차량의 사진을 표시한다.
- 사용자가 과거 차량을 선택해 보고 있어도 새 입차·정산·출차가 발생하면 최신 차량 사진으로 자동 전환한다.
- 이미지 파일이 없거나 읽을 수 없으면 프로그램을 중단하지 않고 `이미지 없음`을 표시한다.

이미지 조회는 `Parking.EdgeService`가 `Edge:ImageDirectory` 아래의 파일명만 허용하는 API로 제공한다. DB와 계약에는 기존 결정대로 전체 경로가 아닌 파일명만 저장한다. `..`, 절대경로, 하위경로 구분자가 포함된 요청은 거부하여 설정 폴더 밖의 파일을 읽을 수 없게 한다.

## 7. 저장 데이터

SQLite에 다음 두 종류의 모니터링 데이터를 저장한다.

### 현재 입차 차량

- 입차 EventId
- 중앙 ParkingSessionId(중앙 처리 전에는 null 가능)
- 사이트·그룹·차로·장비번호
- 차량번호
- 입차시각
- 입차 이미지 파일명
- 중앙 전송 상태와 결과 코드

### 처리 이력

- 처리 식별자(EventId 또는 PaymentId)
- 처리 종류(정산 또는 출차)
- ParkingSessionId
- 사이트·그룹·차로·장비번호
- 차량번호
- 처리시각
- 입차·출차 이미지 파일명
- 정상요금·할인금액·결제금액·결제수단
- 차단기 개방 여부
- 중앙 전송 상태와 결과 코드

결제 요청에는 차량번호와 이미지명이 없으므로 `ParkingSessionId`로 현재 입차 차량을 찾아 표시 정보를 결합한다. 찾지 못해도 정산 행은 저장하며 차량번호와 입차 이미지는 빈 값으로 반환한다.

## 8. 관리 API

- `GET /api/v1/management/status`
  - EdgeService 실행상태, Gateway·중앙 연결상태, 마지막 설정 동기화 시각, 대기 Outbox 수를 반환한다.
- `GET /api/v1/management/entries?limit=1000`
  - 현재 입차 차량을 최신순으로 반환한다.
- `GET /api/v1/management/activities?limit=1000`
  - 정산·출차 처리 이력을 최신순으로 반환한다.
- `GET /api/v1/management/configuration`
  - 현장 캐시에 저장된 현재 설정을 반환한다.
- `GET /api/v1/management/images/{fileName}`
  - 설정된 이미지 폴더에서 LPR 이미지 한 장을 반환한다.

`limit`은 1부터 1,000까지만 허용한다. 잘못된 값은 HTTP 400을 반환한다. 상태 API는 EdgeService 자체가 응답하면 Service 상태를 정상으로 표시하고, 하위 연결상태는 각각 독립적으로 반환한다.

EdgeGateway에는 `GET /health`를 추가한다. 이 API는 Gateway 자체가 실행 중이면 항상 응답하며 중앙 API 연결 여부를 응답 본문에 포함한다. 중앙 확인이 실패해도 Gateway 상태 응답 자체는 HTTP 200으로 반환하여 `Gateway 정상 / 중앙 끊김`을 구분한다.

## 9. 갱신 방식

- EdgeManager는 1초마다 상태와 두 목록을 조회한다.
- 설정은 시작 시 조회하고 마지막 동기화 시각이 변경됐을 때 다시 조회한다.
- 이전 조회 결과와 최신 결과를 비교하여 새 사건이 있을 때만 사진을 자동 전환한다.
- 한 번의 조회가 실패해도 기존 화면 자료를 지우지 않고 연결 끊김 상태만 표시한다.
- 중복 응답이나 재전송으로 같은 식별자가 다시 조회돼도 목록 행을 중복 생성하지 않는다.

## 10. 시험 기준

- 입차 접수 시 현재 입차 목록에 한 번만 나타난다.
- 같은 EventId 재전송은 입차 행을 중복 생성하지 않는다.
- 정산 접수 시 처리 목록에 정산 행이 남고 입차 행은 유지된다.
- 출차 성공 시 입차 행이 삭제되고 처리 목록에 출차 행이 남는다.
- 출차 차단 또는 실패 시 입차 행이 유지된다.
- 정산 후 출차하면 처리 목록에 두 행이 각각 남는다.
- 처리 목록이 1,000건을 넘으면 가장 오래된 행이 삭제된다.
- 새 사건이 발생하면 현재 수동 선택과 관계없이 최신 사진으로 전환된다.
- 이미지 누락과 잘못된 이미지 경로 요청을 안전하게 처리한다.
- EdgeService 연결이 끊겨도 EdgeManager가 종료되지 않고 마지막 자료를 유지한다.

## 11. 완료 기준

- EdgeManager가 상태, 설정, 입차 목록, 정산·출차 목록을 한 화면에 표시한다.
- 입차·정산·출차를 실제 EdgeService API로 전송했을 때 목록과 사진이 정해진 규칙대로 변경된다.
- 기존 입차·출차·요금·결제·Outbox 시험을 포함한 전체 테스트가 성공한다.
